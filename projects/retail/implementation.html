Implementation notes

The Airflow DAG is organized as one task per Medallion layer (bronze_task, silver_task, gold_task), each a PythonOperator/SparkSubmitOperator pair, with explicit upstream/downstream dependencies and a file sensor at the front of the DAG.

Partitioning by sale date keeps daily runs cheap and makes backfilling a specific date range straightforward — a backfill is just re-triggering the DAG for those logical dates.

Data-quality checks are implemented as their own DAG tasks between layers, comparing row counts and null rates against the previous run rather than hardcoded thresholds, so the checks adapt as data volume grows.
